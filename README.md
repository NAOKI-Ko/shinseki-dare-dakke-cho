# 親戚だれだっけ帳(仮称) — 和帳シリーズ第3作(v1+オンボーディング統合版)

法事や帰省の前に、親戚の顔・名前・続柄をサッと確認できる帳面アプリ。
初回起動時に自分の名前を登録すると、以後その人を起点にした
**つながりマップ**(蓄積型・パン/ズーム可能なキャンバス)で
関係を辿りながら可視化できる。

## 動作要件
- Xcode 15以上 / iOS 17以上(SwiftData・PhotosUI使用)
- 外部ライブラリなし・通信ゼロ(シリーズ共通方針)

## ファイル構成(9本)
| ファイル | 役割 |
|---|---|
| `ShinsekiChoApp.swift` | エントリ+和帳モダンテーマ(シリーズ共通) |
| `Models.swift` | Person(isSelfフラグ含む) / Gathering + **RelationshipManager** |
| `ContentView.swift` | 「自分」未登録ならOnboardingViewへ、登録済みなら3タブへ分岐 |
| `OnboardingView.swift` | 初回起動時、自分の名前を登録する導入画面 |
| `PersonListView.swift` | 人物一覧(顔写真グリッド)+登録フォーム |
| `PersonDetailView.swift` | 人物詳細+**RelationEditorView**(配偶者・親・子の登録) |
| `ConnectionMapView.swift` | **つながりマップ(核心機能)**。`FamilyGraphStore`(グラフ構築)+`FamilyGraphView`(パン/ズーム描画) |
| `GatheringListView.swift` | 集まり(法事・帰省)の一覧・出席者管理 |
| `SettingsView.swift` | 設定+「自分」の変更 |

## 起動フロー

1. アプリ初回起動時、SwiftDataに`isSelf == true`の人物が存在しないため
   `ContentView`は`OnboardingView`を表示する
2. 名前を入力して「はじめる」を押すと`isSelf: true`の`Person`が作成される
3. `@Query`のリアクティブ性により、明示的な画面遷移コードなしで
   自然に3タブ画面へ切り替わる
4. 2回目以降の起動では、既に自分が存在するため直接タブ画面が表示される
5. 設定タブの「変更する」から、後で自分を再指定することも可能

## 最重要確認事項が2つ

### ①関係の双方向整合性(Models.swift の RelationshipManager)
SwiftDataの自動inverseに頼らず、`setSpouse` / `addParentChild` 等の
関数を通じてのみ関係を変更する設計。壊れると「Aの子はBなのに、Bの親は
空欄」のような矛盾データが発生する。

### ②つながりマップの蓄積・安定配置(ConnectionMapView.swift の FamilyGraphStore)
- 自分(isSelf=true)を起点(level=0)にグラフを初期化する
- ノードをタップすると「置き換え」ではなく「拡張」される: 親はlevel-1、
  子はlevel+1、配偶者は同level に、**まだキャンバスに存在しなければ**
  新規追加。既に存在すれば新規ノードを作らずエッジのみ追加
- **一度配置したノードのlevel/slotは変更しない**(再配置による位置の
  ジャンプを防ぐ)
- ピンチでズーム、ドラッグでパン。右下の照準ボタンで表示をリセット

```
和帳シリーズ第3作「親戚だれだっけ帳(仮称)」の新規プロジェクト構築です。
初回オンボーディングを含む完成形の一式です。

1. Xcodeプロジェクトを新規作成し、添付の.swift 9ファイルを組み込む
   - iOS 17.0以上 / Bundle IDは com.naoki-ko.shinsekicho で仮置き
   - Info.plistに ITSAppUsesNonExemptEncryption = NO を追加

2. 関係性同期のユニットテストを作成して実行(最優先):
   - addParentChild / setSpouse の双方向反映、配偶者の付け替え時に
     旧配偶者のspouseがnilに戻ること、detachAllで全関係が解消される
     こと、siblingsが共通の親から正しく導出されることを確認
   - 保存・アプリ再起動後も関係が正しく復元されることを確認

3. つながりマップ(FamilyGraphStore)のユニットテストを作成して実行
   (最優先):
   - 自分(A)・親(B)・配偶者(C)・子(D)からなる関係を作成
   - store.reset(with: A); store.expand(A) を実行 →
     ノードにA・B・C・Dが含まれ、エッジがA-B(親子)・A-C(配偶者)・
     A-D(親子)の3本存在することを確認
   - Bのlevelが-1、Dのlevelが+1、Cのlevelが0(Aと同じ)であることを確認
   - Bを展開(store.expand(B))した際、Bの配偶者がCと共通の子Dを持つ
     場合、Dの新規ノードが重複して作られず、既存のDへのエッジのみが
     追加されることを確認(このテストが最重要)
   - 一度配置されたノードのlevel/slotが、その後の別ノードのexpandに
     よって変化しないことを確認

4. オンボーディングのUIテスト:
   - アプリを初めて起動した状態(SwiftDataストアが空)では、タブバーが
     表示されず、オンボーディング画面(名前入力)が表示されること
   - 名前を入力せずに「はじめる」を押せないこと
   - 名前を入力して「はじめる」を押すと、タブ画面(「親戚」タブ)に
     自然に遷移すること
   - アプリを再起動すると、オンボーディングは表示されず直接タブ画面が
     表示されること
   - 設定タブに、オンボーディングで入力した名前が「自分」として
     表示されていることを確認

5. クリーンビルド後、その他のUIテスト:
   - 親戚を4〜5人登録し、関係編集で配偶者・親・子を設定
   - 人物詳細のつながりマップで、自分がキャンバス中心に表示されることを確認
   - 未展開のノードに＋バッジが表示され、タップすると新しいノードが
     周囲に追加され、＋バッジが消えることを確認
   - ピンチでズーム、ドラッグでパンができることを確認
   - 右下の照準ボタンでスケール・オフセットが初期値に戻ることを確認
   - 集まりを1件作成し出席者を追加、人物詳細に反映されることを確認
   - 顔写真を1件登録し、一覧のグリッドに反映されることを確認
   - アプリ再起動後もすべてのデータ・関係・「自分」設定が保持される
     ことを確認

6. 制約: 外部ライブラリ禁止 / 通信・SDK追加禁止 / UI日本語 /
   和帳モダンのテーマ定義を変更しない

各画面のスクリーンショット(ライトモード。オンボーディング画面と、
つながりマップはノードが5〜6個展開された状態のものを含める)、
および全ユニットテストの結果(pass/fail一覧)を報告してください。
```

## 備考
- v1では「配偶者は1人まで」「親は最大2人まで」という制約をUIで
  緩く課している。ステップファミリー等の複雑なケースは自由記述
  (relationNote)で補う想定
- つながりマップのレイアウトは、厳密な家系図(交差線の最小化など)を
  狙わない簡易な世代レイヤー配置。個人利用規模(数十人程度)であれば
  実用上問題ない想定
- 名称候補: 親戚だれだっけ帳 / つながり帳。ストア文言検討時に決定
- 価格は600円を想定(他シリーズの300円より高いが、つながりマップという
  可視化機能を持つ上位アプリとして説明文で位置づける)
